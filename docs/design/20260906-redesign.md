# 霜民鍵盤總教練 — 生涯改版設計規格（2026-09-06）

## 這份文件要解決什麼

目前的遊戲只有單一賽事：2027 世界十二強，前提是「中華隊剛在 2026 經典賽拿第 13 名」。
使用者要求改成一段**跨年度的勵志生涯**：

1. 時間線從 2024 年末開始，前任總教練奪下十二強冠軍、終結日本 27 連勝後光榮引退
2. 納入中華隊所有成棒級賽事
3. 角色可以是職棒教練／賽事教練／賽事總教練，從基層往上爬
4. 不要每場比賽決定先發投手
5. 參考 yakyolife 的節奏重新設計

第 5 點與第 2 點之間有一個必須先解開的矛盾：yakyolife 的**遊玩單位是「一年」**，
整個球季用「擲骰分配 → 3 張事件卡 → 年度大賽名次一行字」解決，完全不模擬比賽。
而本作是逐球模擬、一屆 10 場、約 50 個提示。照現在的節奏做 8 個賽事會變成
400+ 個提示，沒有人玩得完。解法是改變遊玩單位（見「混合節奏」）。

## 設計決策（已與使用者確認）

| 項目 | 決定 |
|---|---|
| 遊玩單位 | **混合**：多數比賽自動結算成一行比數，只有「重點戰」進入逐球模式 |
| 角色階層 | **從基層往上爬**：中職教練 → 國家隊教練團 → 總教練 |
| 中職球季 | 一行結算 ＋ 事件卡（**階段二才做**） |

| 舊種子碼 | **不保留相容**（使用者明示不在乎） |

## 混合節奏

### 一屆賽事的流程

```
賽前：徵召 28 人 ＋ 全隊跑壘方針（積極／平衡／保守）    1 個提示
賽前事件卡 ×2（3 選 1，明碼機率）                      2 個提示
預賽：自動結算，一場一行比數                            0 個提示
★ 重點戰：逐球模擬，最多 5 個關鍵決策                   一級 2 場／二級 1 場
賽後：名次、聲望變化、能力點分配（可自動配置）           1 個提示
```

一級賽事約 14 個提示，二級約 9 個。

### 自動結算怎麼跑

**用同一支 `simulateGame` 引擎跑，只是不產生玩家提示。**
這點是硬性要求：既有的平衡、棒球規則、決定論全部保留，
不會出現「自動結算的世界」與「手動打的世界」數值不一致。

自動結算時由新的 `POLICY_COACH` 代替玩家決策，**它的判斷品質由教頭能力決定**。
具體規則（避免「能力影響判斷」變成一句沒有實作的話）：

```
1. 每個選項算出期望值 EV = odds.final × swing − (1 − odds.final) × swing
   （swing 就是引擎已有的 SWING_BASE × (1 − baseRate)）
2. 依 EV 由高到低排序
3. 教頭「用兵」決定會不會選到最好的那個：
      失誤率 = clamp(0.45 − (用兵 − 50) / 25 × 0.18, 0.05, 0.55)
      擲一次骰，失誤就退而選第二好的（只有一個選項時不適用）
4. 這個擲骰走專屬的 RNG key（.../autopolicy），不影響比賽本身的隨機流
```

用兵 22 的菜鳥約 40% 的時候會選錯，用兵 90 約 16%。
這讓教頭能力在自動結算的比賽裡也有意義，而不是只影響那兩場重點戰。
測試會斷言「用兵高的自動結算勝率必須高於用兵低的」。

### 哪些是重點戰

由賽事定義標記，判準（依序）：

1. 決賽／獎牌戰
2. 對日本或韓國
3. 淘汰局面（輸了就出局）

一級賽事取前 2 場，二級取前 1 場。

## 角色階層與聲望

### 三種身分

| 身分 | 名單權 | 賽中決策 | 說明 |
|---|---|---|---|
| `CPBL_COACH` 中職教練 | 無 | 無 | 不參與國際賽，只在新聞裡看到結果（階段二才有內容） |
| `NT_COACH` 國家隊教練團 | **建議**（系統可能不採納） | 最多 2 個／場 | 決定權不在你手上，這個挫折感是往上爬的動力 |
| `NT_MANAGER` 總教練 | 完整 | 最多 5 個／場 | 完整權限 |

### 聲望

一條 0–100 的 `prestige`，與既有的民調／協會信任／士氣並列。

- **晉升**：`NT_COACH` 門檻 45、`NT_MANAGER` 門檻 75
- **降職**：掉到 25 以下退回上一層；`CPBL_COACH` 再掉到 0 就是生涯結束
- **變動來源**：賽事名次、是否擊敗日韓、輿論事件、投手用量爭議

階段一固定為 `NT_MANAGER`，聲望仍然計算與顯示，但不觸發升降——
這樣階段二接上去時不需要改資料結構。

## 軟體架構調整

以下都是量測後有證據的問題，不是憑感覺重構。

### A. 刪掉做不到的承諾（優先）

`docs/CONTRIBUTING.md` 第 5 節寫著「`content/v1/` 凍結，新內容進 `v2/`，
存檔綁定 pack 版本，舊種子永遠用舊 pack 重播」。

**程式碼根本做不到**：`core/` 寫死 `import '../../content/v1/...'`，
`save.js` 寫入 `contentPack: { version: 'v1' }` 但沒有任何程式碼讀它。

使用者已明示不在乎舊種子碼相容，所以不做內容包注入。對應處置：

1. 刪除 CONTRIBUTING 第 5 節的版本凍結承諾，改寫成誠實的說法：
   「內容改動會讓既有種子碼跑出不同結果。這是已接受的取捨，不提供跨版本重播。」
2. 移除 `SaveFile.contentPack` 這個沒人讀的欄位
3. `content/v1/` 更名為 `content/data/`——留著 `v1` 卻不做版本控制只會誤導後來的人

### B. 拆分 `career.js`

695 行、13 個匯出、14 個函式，混了六種責任。新的多年迴圈只會讓它更糟。

| 新檔案 | 責任 |
|---|---|
| `core/career/loop.js` | `runCareer` 狀態機、`newCareer` |
| `core/career/postgame.js` | 賽後處理（負荷、傷病、士氣） |
| `core/career/allocation.js` | `applyGrowth`、`applyAllocation`、`autoAllocate` |
| `core/career/endings.js` | `pickEnding`、`computeMeterDelta` |
| `core/career/choices.js` | 各種 decision optionId 的編解碼 |
| `core/career/coach.js` | `COACH_ATTRS` 與標籤常數 |
| `core/career/roster.js` | 維持現狀 |
| `core/career/prestige.js` | 聲望與角色（階段一只算不觸發） |

**純搬移，不改行為。** golden 種子測試會守著這一點。

### C. 解掉分層滲漏

`core/career/roster.js` 目前 import `core/sim/atBat.js` 的 `carryOverPitches`。
那是「投球負荷 → 有效疲勞」的領域規則，不是模擬內部細節。
移到 `core/domain/workload.js`，由 `sim` 與 `career` 各自 import。

### D. 拆 `types.js`

437 行單檔，加上日曆／角色／聲望會破 600。依領域拆成
`types/player.js`、`types/coach.js`、`types/game.js`、`types/career.js`、`types/content.js`，
保留 `types.js` 作為 re-export 的入口，這樣既有 import 不用全改。

### E. 賽事日曆資料化

`content/data/calendar.js`：一條有序的清單，每格是一個賽事定義。
`core/career/loop.js` 迭代這條清單，而不是寫死 `PREMIER12_2027`。

賽事定義新增欄位：`tier`（1 或 2）、`keyGameRules`、`prestigeDelta`。

## 階段切分

### 賽事之間的條件分支

日曆不是一條無腦的直線，有兩個分支點：

**2028 奧運最終資格賽——只在沒拿到 2027 門票時才打。**
2027 十二強拿到亞洲門票的話，這一格跳過，敘事帶過
（「你不用打資格賽了。三月你在台北看別人打。」）。
這讓 2027 的成績有真實後果：贏了少打一關，輸了還有一次機會但要在主場承受更大壓力。

**2028 奧運——兩條路都沒過就進不去。**
2027 沒拿到門票、資格賽又失敗的話，生涯在 2028 年 3 月結束，
結局為「沒能帶隊上奧運」（一個獨立結局，不是被解僱）。
階段一到此為止。階段二能不能延續到 2030 經典賽，取決於 WBSC／MLB 何時公布正式賽程。

### 階段一（本次實作）

**含**：新時間線與賽事日曆（2024末→2028，六個賽事）、混合節奏（自動結算 ＋ 重點戰）、
`POLICY_COACH`、一屆一次的賽前設定、移除每場選先發、聲望計算與顯示、
架構調整 A–E、對應測試與文件。

**不含**：中職球季、角色階層的升降觸發（固定為總教練）、2029 之後的賽事。

**階段一的結局清單**（每一個都必須真的達得到，由平衡護欄逐一檢查）：
`奧運金牌` / `奧運獎牌` / `進了奧運但沒獎牌` / `沒能帶隊上奧運` / `被揃下台`。

階段一結束時：可以從 2024 年末接手，打完 2025 亞錦賽、2026 WBC、2026 亞運、
2027 十二強、2028 資格賽、2028 奧運，拿到金牌或被炒。

### 階段二（之後）

中職球季（一行結算 ＋ 事件卡）、角色階層升降、2029+ 賽事、
更多事件卡與決策模板。

## 測試策略

延續既有做法：所有新機制都要有對應測試，而且測試本身要用「植入違規」驗證過會失敗。

**新增**

- 賽事日曆：每個賽事都走得完、名次獎勵與淘汰名次對得上、重點戰數量符合等級
- 自動結算：與逐球模擬用同一支引擎（斷言事件流結構相同，只差沒有 DECISION）
- `POLICY_COACH`：教頭能力高的自動決策勝率必須高於能力低的
- 聲望：升降門檻、變動來源、不會超出 0–100
- 架構搬移：拆檔前後 golden 種子結果必須完全相同（先拆檔跑一次確認，再改時間線）

**既有**：決定論、golden 種子、棒球規則、遊玩流程、純度掃描、內容檢查、平衡護欄全部保留。

**平衡護欄要新增**：整段生涯的奧運金牌率、經典賽奪冠率、被解僱率、各賽事名次分布。

## 已知風險

| 風險 | 對策 |
|---|---|
| 拆檔時不小心改到行為 | 先拆檔、跑 golden 確認完全相同，**再**動時間線。兩件事分開 commit |
| 自動結算與手動模擬產生不同世界 | 硬性要求用同一支 `simulateGame`；測試斷言事件流結構相同 |
| 六個賽事的平衡各自跑掉 | `tools/balance.js` 增加 `calendar` 模式，逐賽事輸出勝率與名次分布 |
| golden 種子整組失效 | 這是預期的（時間線改變）。拆檔階段不得失效，改時間線階段才重生 |
| 節奏仍然太重 | 先做完階段一實測，再決定要不要把二級賽事的重點戰砍到 0 |

規格照做，以下是實作時發現、規格沒預料到的事。

## 1. CONTRIBUTING 的第二個假承諾

第 3 條寫著「`applyEffects` 是唯一能改 `CareerState` 的地方」，
但 `core/effects/` **從來沒有被實作過**，也沒有任何事件卡。
這是同一份文件裡的第二個做不到的規則（第一個是內容版本凍結）。

差別在於這次規格本來就需要它（賽前事件卡），所以**實作它**而不是刪掉它。
`core/effects/apply.js` 233 行，含 `applyEffects`、`evalPredicate`、`selectCast`，
以及一份 `STATE_PATHS` 白名單讓 contentLint 抓得到打錯字的 path。

規則本身也修正得更精確：約束的是**內容**，不是引擎。
`postgame.js`、`allocation.js` 直接改 state 是正常的，它們是引擎機制不是卡片。

## 2. 冠軍卻拿不到奧運門票

第一次跑完整生涯就抓到：2027 十二強**拿了冠軍，但沒拿到門票**。
因為門票規則寫的是「前 4 名且至少擊敗日韓一次」，而那局預賽輸給日韓、一路贏到冠軍。

冠軍隊當然是亞洲最高名次。規則在只有一屆賽事時看起來合理，
放進完整日曆就荒謬了。已改為「前兩名自動取得，第 3、4 名才需要擊敗日韓」。

## 3. 教頭能力太平，導致金牌不可達

第一次量測生涯結局：**奧運金牌 0%**（250 段生涯）。
整個遊戲的勵志前提就是拿金牌，那等於前提不成立。

根因是 P1 就記錄過的「教頭能力影響太平」——能力只透過決策選項的成功率生效，
作用點太少，22 → 90 對日本勝率只從 25% 升到 30%。
四年練上來的能力幾乎不影響結果，養成變成裝飾。

**處置**：新增 `TUNING.atBat.coachQuality`，讓教頭五項能力的平均值直接修正
我方的打席結果（好教練本來就能讓球隊打出更多東西）。
修正後 22 → 27%、90 → 45%，18 個百分點的差距。

**中途踩到的坑**：第一版用刻度中點 50 當基準，結果起始 22 的菜鳥開局就被扣 15%，
對捷克勝率從 66% 掉到 52%，整組基礎平衡都要重調。
改用**起始能力**當基準後，成長變成純粹的上檔，也比較符合「勵志」的調性。

**另一個坑**：常數插入 tuning.js 時字串沒對上，`coachQuality` 變成 `undefined`
→ NaN → 每個打席都判定失誤 → 單場 165 分。typecheck 有抓到，
但我當時把它跟量測寫在同一個指令裡，先看到了離譜的數字才回頭看型別錯誤。

## 4. 「經典賽冠軍」這條勝利條件原本不存在

使用者要的是「奧運金牌**或**經典賽冠軍」，但結局只認奧運——
拿下 2026 經典賽冠軍是隊史級成就，卻不會反映在結局裡。

補上 `wbc_champion` 與 `double_crown`（兩座都拿）之後，
第一版仍然是 0%：因為贏得了經典賽的人幾乎一定進得了奧運，
永遠被奧運結局蓋過。把它提到奧運銀銅之前才真的達得到——
經典賽冠軍本來就勝過奧運銀牌。

這是第三次踩到「寫得出來但達不到的結局」。護欄現在逐一列舉全部七個結局檢查。

## 5. 輸掉四強白拿銅牌

golden 快照露出來的：`洛杉磯奧運棒:銅牌戰資格` → 銅牌結局。
真實奧運輸了四強要打銅牌戰，贏才有牌。免費的獎牌會讓那個結局不值錢。

新增資料驅動的 `StageDef.consolation`（敗部戰），
而不是在引擎裡特判奧運。修正後獎牌率從 11.2% 降到 6.8%。

## 6. 結局統計只看最後一屆

瀏覽器實測時發現結局畫面顯示「戰績 0–2」——那是最後一屆奧運的成績，
不是四年生涯。新增 `CareerState.history`，結局畫面改成完整的四年回顧表。

這個改動不只是修 bug：一份「2025 亞軍 / 2026 第13名 / 2026 金牌 / 2027 冠軍 /
2028 小組出局」的表格本身就是這種遊戲的情緒收尾。

# 奪冠率調校（2026-09-06）

使用者要求把奪冠率提高到約 25%（原本 4.4%）。

## 第一個直覺是錯的

先掃 `TUNING.atBat.coachQuality`：

| coachQuality | 奪冠率 | 滿能力教頭對日本 |
|---|---|---|
| 14 | ~5% | 55% |
| 22 | ~8% | 76% |
| 30 | ~12% | **90%** |
| 38 | 15.8% | ~95% |

到 25% 需要把 coachQuality 拉到 50 以上，那時滿能力教頭對日本是 **100%** ——
後期完全沒有張力，跟「好玩」是反的。這個旋鈕不對。

## 真正的原因

量測玩家在生涯結束時的教頭能力：

```
起始 22 → 結束時平均能力：最低 24.2　中位 35.6　最高 45.4
能力上限平均 64.8
```

**中位玩家四年只練到 35.6，連一半潛力都沒用到。**
我一直拿「滿能力 90」在測 coachQuality 的效果，但真實玩家根本到不了那裡。
「四年養成」在數值上幾乎沒有發生 —— 這才是奪冠率上不去的原因。

## 處置

新增 `TUNING.reward.pointsMultiplier`，把名次獎勵整體放大。

| 倍率 | 奪冠率 | 門票率 | 結束時能力中位 |
|---|---|---|---|
| 2 | 13.0% | 74% | 48.5 |
| 3 | 22.4% | 82% | 56.5 |
| **3.4** | **24.4%** | 86% | ~58 |
| 5 | 38.4% | 92% | 64.1 |

採用 **3.4**。這個做法比拉 coachQuality 好的地方在於：

- 成長真的被看見（進度條在動），而不是把每一點的效果放大
- 個別比賽沒有被玩壞。典型玩家（能力 56）對日本 50%、韓國 67.5%、委內瑞拉 55.8%，
  對照起始的 27.5% / 45% / 35% —— 從弱隊變成平起平坐，但沒有變成輾壓

## 順手修掉的護欄缺陷

`tools/balance.js` 的勝率區間檢查**不管 `--coach` 傳什麼都套用同一組期望值**，
而那個區間是為起始能力設計的。用 `--coach 90` 檢查成長效果時，
55% 的勝率會被判成失敗。已改為只在起始能力時檢查。

## 調整後的護欄

奪冠率目標從「2–20%」改為「18–32%」，門票率從「15–70%」改為「50–92%」。
新增「被解僱率不得低於 0.5%」—— 風險消失的話，成就也就不值錢了。
